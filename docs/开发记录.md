## 第一阶段 · 会话状态持久化（2026-11-23）

**分支**：`feat/phase1-state-persistence` ｜ **PR**：#1 ｜ **规模**：3 个文件，+70 / −29

### 一句话

修掉了「学完一节课，重启就忘」—— 学习状态从来没写进磁盘。

### 改之前（问题）

| 现象 | 根因 |
|---|---|
| 每轮对话结束后，知识点、薄弱点、阶段轨迹全部清零 | `learn:reply` 每轮现场拼一个空壳 `SessionState`（`points: []`、`trail: []`、`goal: ''`） |
| 重启后只能回到「开场」 | `saveSession()` 全仓库只在自测里调用过 1 次，生产路径从不写盘 |
| 推进阶段时历史丢失 | `advancePhase()` 为调 `moveTo` 临时造空状态，只把 `phase` 写回索引 |
| 判完对错就查不到"刚才是哪道题" | `judgeAnswer` 只收到临时拼接的字符串，判定结果没有落盘 |

### 改了什么

| 文件 | 改动 |
|---|---|
| `src/main/learn/session.ts` | 新增 `loadSessionState()`：从磁盘读完整状态，缺字段安全兜底；新增 `recordCheck()`：题目 + 知识点 + 结论绑定保存；`SessionState` 增加 `lastQuestion` / `lastCheck` |
| `src/main/learn/session-store.ts` | `advancePhase()` 改为读-改-写完整状态，推进时不再丢 `goal / points / weaknesses / trail` |
| `src/main/index.ts` | `learn:reply` 载入完整状态（不再拼空壳）；检验阶段记录 `lastCheck`；每轮结束 `saveSession` |

七阶段状态机的转移约束（`TRANSITIONS`）**没有改动**。

### 怎么验证的

```
tsc -p tsconfig.node.json --noEmit   → 0 error
pnpm build                           → 通过
状态机单测                            → 17 passed / 0 failed
```

单测覆盖的关键断言（都能复现给评委看）：

- `goal / points / weaknesses / activeIndex` 写入后能原样读回
- **推进阶段后 `points`、`goal`、`trail` 仍然存在**（旧实现必挂）
- `lastCheck` 的题目与判定结果落盘
- 状态文件缺失时安全兜底，不抛异常
- 非法阶段转移仍被拒绝

### 讲的时候可以说

> 我们把「学习进度」从模型脑内搬到了磁盘上。以前每轮对话程序都拿一个空的进度表去问模型，
> 模型再聪明也接不上上一句；现在是程序持有状态、模型只负责这一步的内容。
> 这是整个教学闭环能跑通的前提 —— 没有它，后面所有"根据上次的表现调整教学"都无从谈起。

### 对应验收清单

覆盖 10 项里的 **7 项**：创建会话保存完整状态、目标持久化、探测结果保存、知识点列表保存、当前知识点记录、收尾总结、重启恢复。
第 6/7 项（出题上下文、错因驱动调整）留到第二阶段。

## 第二阶段 · 自动阶段推进（2026-11-23）

**分支**：`feat/phase2-auto-advance` ｜ **PR**：#2 ｜ **规模**：4 个文件

### 一句话

让七阶段自己会走：模型只产出结构化标记，走不走、走到哪一步，由程序判断。

### 改之前（问题）

| 现象 | 根因 |
|---|---|
| 阶段要人点按钮才动，或者模型自己说"下一步我们…"就乱跳 | 推进入口是 `session:advance` IPC，靠界面触发 |
| 目标、薄弱点、知识点在会话状态里永远是空数组 | 没有任何代码往里写，模型也没有表达渠道 |
| `[知识点: …]` 标记被当成"经历"记进记忆 | 解析器把 `知识点` 映射成了 `experiences`，`kind === 'point'` 的分支从没执行过 |

### 改了什么

| 文件 | 改动 |
|---|---|
| `src/main/memory/extract.ts` | 标记协议扩到 4 种学习事件：`[目标:]` `[薄弱点:]` `[知识点:]` `[讲完:]`；修正 `知识点` 的映射；标记仍从正文里删除，学生看不到 |
| `src/main/learn/session.ts` | 新增 `decideNextPhase()`：按阶段完成条件判断下一步（纯函数，可单测）；新增 `addSessionPoint()`；`phaseGuide` 按阶段告诉模型该吐哪个标记 |
| `src/main/learn/session-store.ts` | 新增 `setPhase()`：状态已落盘时只同步索引，避免重复写 |
| `src/main/index.ts` | 标记 → 更新状态 → 程序判断推进 → 落盘并同步索引；模型不再能自己决定跳步 |

### 推进条件（答辩可以直接讲这张表）

| 当前阶段 | 什么时候自动进入下一步 |
|---|---|
| 开场 | 第一轮对话结束 |
| 目标确认 | 收到了 `[目标: …]` |
| 学情探测 | 至少收到 1 个 `[薄弱点: …]` |
| 知识点拆解 | 至少收到 1 个 `[知识点: …]` |
| 逐点教学 | 所有知识点都被 `[讲完: …]` 标记过 |
| 阶段检验 | 答对且还有没讲的点 → 回教学；答对且全讲完 → 收尾；答错 → 回教学补讲 |
| 收尾 | 停止（等新目标） |

条件不满足就停在原地，绝不会跳步（`TRANSITIONS` 的约束仍然生效）。

### 怎么验证的

```
tsc -p tsconfig.node.json --noEmit   → 0 error
pnpm build                           → 通过
单测                                 → 31 passed / 0 failed
（标记解析 6 条 + 推进规则 15 条 + 端到端 10 条）
```

端到端那条把整条链路跑了一遍：开场 → 目标 → 探测 → 拆解 → 讲三点 → 检验，**七轮对话七次自动推进**，并且重启后知识点、目标、轨迹都还在。

### 讲的时候可以说

> 我们没有把七个阶段一股脑塞给模型，也没有让模型自己说"我们进入下一步"。
> 模型只负责这一步的内容，外加几个方括号标记（目标、薄弱点、知识点、讲完）；
> **走不走、走到哪一步，是程序根据状态判断的** —— 所以流程稳定、可复现、可以审计。

### 对应验收清单

补上了第 6、7 项（出题上下文、错因驱动调整），**10 项验收全部覆盖**。
